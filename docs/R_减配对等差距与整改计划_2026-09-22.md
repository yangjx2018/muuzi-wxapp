**产品定位（你的要求）**：微信小程序 = **减配版 MuuZi 手机端**  
- **减配**：不做首页/Discover/Feed/Digest、不做中心 Muu Tab、不做 Apple/Google、Studio 不内嵌 web-view、支付走微信 JSAPI、E2EE 首期诚实延后。

## 1. 预期目标（减配版定义）

### 1.1 必须对齐（减配后仍要对等）

| 模块 | 预期 |
|------|------|
| 登录 M0 | 登录页结构/文案 1:1；密码可用；微信登录主路径可用；注册/找回可达；未登录拦 Tab；Join 访客除外 |
| 连接 M1 | Hub、名片、面对面/扫码、话题 CRUD、FieldTalk 文字+语音保存、Join 访客，主路径与 App 同数据 |
| 我 M2 | 主页壳、设置树无断链、编辑发布、店铺/留言/主体/空间等读写主路径；Studio 复制链接 |
| 消息 M3 | 工作区/筛选/私信/邀请/会话文本·附件·回复·表情·设置；布局与操作贴近 MessagesScreen |

### 1.2 允许减配 / 平台对等（不算缺陷）

| 项 | 说明 |
|----|------|
| 三 Tab vs 五 Tab | 不做首页、不做中心 Muu |
| 微信登录 vs Apple/Google | 强制替换 |
| JSAPI vs IAP | 未配置须诚实失败 |
| Studio | 复制链接，无 web-view |
| E2EE | 首期明文互通；密文等待/失败；加密房禁发 |
| 赠卡 | 与 App 同 stub |
| Muu 完整对话 | 设置入口诚实占位 |
| 原生 tabBar | 无法 1:1 复刻胶囊 BottomNav，但选中态/未读红点应对齐语义 |

### 1.3 PRD 禁止

- 静默砍功能却仍宣称 1:1  
- 假成功（支付、同步、保存、解密）  
- 用「功能未开放」掩盖未实现的微信登录
